# Audit, 28 October 2026

## Summary

The plan is coherent overall. `index.html` matches the approved preview (I compared it with the artifact linked in the brief, section 2), and all nine hex values match the brief. Of the 18 points in `CLAUDE.md` 3.3, 16 are confirmed, 1 is confirmed but its example is wrong (15), and 1 just needs a sign-off (6). I found 24 more (7 of them are "Fine as is").
**Two things block a clean build.** (a) Olive text on mauve poudré has a contrast of 4.37:1, below the WCAG AA minimum of 4.5:1, so acceptance check 11 cannot pass without a small color decision (finding 19). (b) The page scrolls sideways between about 700px and 1180px wide, including 768px (finding 20).
**Blocking only later phases:** the hosting provider (18), the domain name (32), and whether the address and phone number in the brief may be used (17, 29). There are 22 questions below. Most can be answered in a word.

How I checked: I read the three files in full, looked at all 35 images (dimensions, colors, edges), rendered the page in Chromium at 360, 390, 768, 1280 and 1440px (plus intermediate widths) to measure overflow and the displayed size of each image, computed contrast ratios, and read npm metadata for the font package. I installed nothing and changed no file except this one.

## Owner decisions

The owner answered all 22 questions on 28 October 2026. The answers are recorded in `docs/BRIEF-site-goundo.md`, section 10, and the matching open items in its section 8 are closed.

## Build plan after the audit

Each phase is one commit on the working branch. At the end (or at any point you choose), a pull request lets you see every change and merge it into `main`.

- **Phase 1, repository.** No `git init` (finding 36). Add `.gitignore` and `README.md`. Move the unused images to `brand/` (14). Add `TODO-LEGAL.md` (30).
- **Phase 2, complete document.** Doctype, `<html lang="fr">`, head and body, charset, viewport. Self-hosted fonts per Q9, with the Gloock and regular Instrument Sans files preloaded. Remove the preview leftovers (13). Then apply the approved findings: 1–4, 8 (meta description), 9, 19, 20–23, 26. Update the brief in the same commit for every approved design rule change (1, 19, 42).
- **Phase 3, decided content.** The real e-mail address everywhere, with hardcoded `mailto:` links (7, 12). The `BOOKING_URL` setup for Doctolib (24, Q22).
- **Phase 4, mentions légales.** Separate page or section per Q11. Address and phone per Q12. Host per Q13. Placeholders for the rest (RPPS, Ordre council). Pre-deploy check for placeholders (34).
- **Phase 5, images.** WebP and `<picture>` with `display: contents` (35), width and height attributes, lazy loading below the fold only. Portrait at 640×800, or larger if Q15 brings a better file. Before/after screenshots.
- **Phase 6, favicon, sharing, search.** I show you the two favicon options and the sharing image before committing them. `robots.txt` and `sitemap.xml` once the domain is known (Q14). Structured data only after the address is approved.
- **Phase 7, deployment.** Connect the host to the GitHub repository, set up the domain, HTTPS and the `www` redirect, and put the final host details into the mentions légales. Final screenshot comparison with the approved preview.
- **Run before every phase is called done:** the acceptance checks in `CLAUDE.md` §11. Today checks 1 (overflow, finding 20), 2 (validation, finding 21) and 11 (contrast, finding 19) fail; the fixes above address all three.
